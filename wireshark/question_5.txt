This lab shifts focus from the application layer (HTTP) down to **DNS (Domain Name System)**, which translates human-readable domain names (like `ietf.org`) into machine-readable IP addresses.

To easily isolate DNS packets in Wireshark, type **`dns`** into your top display filter bar.

Let's break down exactly how to answer each question step-by-step.

---

## Part 1: Analyzing `www.ietf.org` in Wireshark

### a) Transport Protocol (UDP vs TCP)

* **How to find it:** Click on any DNS query line (labeled `Standard query 0x... A www.ietf.org`). Look at the middle pane just above the `Domain Name System (query)` row.
* **Your Answer:** They are sent over **UDP** (User Datagram Protocol). DNS uses UDP because it is fast and lightweight, requiring no connection setup handshake for quick lookups.

### b) Destination and Source Ports

* **How to find it:** Click the query packet, expand the **User Datagram Protocol** line in the middle pane, and check the ports. Then click the response packet and do the same.
* **Your Answer:** * The destination port for the DNS **query** is **53**.
* The source port of the DNS **response** is **53**.
* *(Note for test: Port 53 is the well-known standard port reserved worldwide for DNS services).*

### c) Target IP Address vs Local DNS Server

* **How to find it:** Look at the **Destination** column for your DNS query packet. Next, open your computer's Command Prompt (cmd) or Terminal, type `ip address` (or `nslookup` on any OS), and look for your **DNS Servers** IP address.
* **Your Answer:** The query is sent to your local router or network's DNS resolver IP (e.g., `192.168.1.1` or `8.8.8.8`). **Yes, these two IP addresses are the same**, because your computer naturally routes all domain queries directly to your configured local DNS server.

### d) Examining the DNS Query Message

* **How to find it:** Click the DNS query packet. In the middle pane, expand **Domain Name System (query)** $\rightarrow$ **Queries** $\rightarrow$ **`www.ietf.org`**.
* **Your Answer:** * The **Type** of query is **A** (which stands for Address record, used to map a hostname to an IPv4 address).
* **No**, the query message does not contain any "answers". The Answers count field is `0` because your computer is the one asking the question; it doesn't have the answer yet.

### e) Examining the DNS Response Message

* **How to find it:** Click the DNS response packet (labeled `Standard query response 0x...`). In the middle pane, expand **Domain Name System (response)** and look for the **Answers** dropdown.
* **Your Answer:** It usually provides **1 or 2 answers** (depending on whether the site uses a CDN or has multiple servers). Each answer contains the domain name, the type (A), the TTL (Time to Live), the data length, and the actual resolved **IPv4 Address** of the server.

### f) Subsequent TCP SYN Packet

* **How to find it:** Change your Wireshark filter bar from `dns` to **`tcp`**. Look at the very next packet sent right after your DNS resolution—it will be a `[SYN]` packet attempting to establish an HTTP connection. Check its **Destination IP**.
* **Your Answer:** **Yes**, the destination IP address of the TCP SYN packet matches exactly one of the resolved IP addresses provided in the DNS response message. Your browser immediately uses the IP it just learned to start talking to the website.

### g) DNS Queries for Embedded Images

* **Your Answer:** **No**, your host does not issue new DNS queries for each image.
* **Explanation:** Because all the images on `www.ietf.org` are hosted on the exact same server as the main website, your computer already knows that server's IP address. It caches the DNS result locally, preventing unnecessary network traffic.

## Part 2: Running `nslookup –type=NS mit.edu`

For this part, you will open your computer's Command Prompt/Terminal, type `nslookup –type=NS mit.edu` and press Enter. This tells the system: *"Find the Name Servers (NS) responsible for managing the mit.edu domain."*

### h) Target IP Address

* **Your Answer:** The query is sent to your **default local DNS server IP address** (the same IP address found in question **c**, such as your home router or school DNS gateway).

### i) Examining the nslookup Query Message

* **Your Answer:** * The **Type** of this DNS query is **NS** (Name Server record).
* **No**, the query message contains `0` answers because it is an outbound question originating from your machine.

### j) Examining the DNS Response Message

* **Your Answer:** * The response provides the authoritative name servers for MIT, which typically include strings like **`w20ns.mit.edu`**, **`bitsy.mit.edu`**, and **`astronomy.mit.edu`**.
* **Yes**, standard DNS responses include an "Additional Records" section that explicitly attaches the corresponding IPv4 and IPv6 addresses for those specific name servers so your computer knows how to reach them immediately if needed.
